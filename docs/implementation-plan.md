# План реализации и выпуска

1. Создать отдельный приватный `maxbot-v2`, FastAPI/SQLite-каркас, secrets, единственный вход, HTTPS, резервное копирование и пробное восстановление с отдельным ключом.
2. Перенести границу PyMax и хранение сессий; сделать группы, прокси и гостевое подключение. Chat ID закреплять автоматически первым аккаунтом; несовпадение следующего отклонять.
3. Сделать общий версионированный пул, сохранённые дни/прокси, слоты и журнал; по одному worker на группу; восстановление, общий стоп, статусы ошибок.
4. Добавить компактную панель и гостевой интерфейс: расписание, proxy label без реквизитов, статус и безопасная причина блокировки.
5. Добавить CI и выпуск на конкретном commit SHA. На VPS развёртывать отдельным портом и томом; проверить HTTPS и фиктивный адаптер. До подтверждения объёма разрешённых действий держать MAX gate закрытым. Перед переключением остановить старое расписание и архивировать данные. Переключение Caddy и откат должны сохранять старую установку с остановленным v2.

## Реализация этого репозитория

Сделаны: первичная схема БД, авторизация владельца, группы/прокси/ссылки, гостевой OTP/cloud-password bridge, версионный пул, weekly slots, sender ledger, group worker manager, простая панель, Docker/Caddy конфигурация, backup/restore команды и тесты SQLite. Следующие эксплуатационные gates: CI workflow и end-to-end нагрузочные проверки с FakePyMax; пробный Docker restore; реальная MAX проверка может выполняться только после установки и проверки разрешения.
