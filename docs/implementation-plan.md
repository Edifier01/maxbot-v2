## Критерий завершения

Полный кодовый выпуск завершён, когда GitHub PR содержит тесты и документацию, CI проходит, а production backup/restore проверен. Полный операционный выпуск требует дополнительно совпадающего SHA локального `main`, GitHub и VDS и подтверждённого реального MAX-сценария. В `docs/change-log.md` отдельно отметьте, какие из этих стадий действительно завершены.

## Осталось

Кодовая часть PR №2 завершена: PR слит коммитом `7eeb752`, после него документационный статус отправлен в `main`; локальная и GitHub ветки были синхронизированы fast-forward. Сверяйте точную текущую ревизию командами `git rev-parse HEAD origin/main`. Все 6 PR checks прошли; post-merge docs-only push тоже прошёл CI. Панель хостинга подтвердила VM Ubuntu 24.04 с диском 60 GB, но не показывает app revision и Docker volumes. Перед выпуском на VDS нужно получить доступ к ОС и:

1. Прочитать SHA checkout, конфигурацию Compose, версию образа, тома и журналы; затем штатно остановить приложение.
2. Сохранить согласованную резервную копию SQLite и зашифрованных сессий, отдельно сохранить ключи и проверить восстановление в отдельной директории без отправки сообщений.
3. Развернуть конкретный SHA `main` и сверить `/health.revision`, HTTPS/Caddy, адрес клиента и отсутствие открытого порта приложения.
4. На согласованном тестовом аккаунте проверить SMS, авторизацию, членство, сохранение сессии и вход после рестарта. Реальную отправку разрешать только в согласованную тестовую группу.

Не удаляйте другие ветки, worktree, production-данные или секреты во время оставшихся эксплуатационных шагов.
