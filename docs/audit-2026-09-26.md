Старые аудиты используются как история; выводы ниже воспроизведены на текущем коде и отдельной тестовой SQLite с фиктивным PyMax.

Раздельный маршрут оставлен на уровне приложения: назначенный прокси должен быть действительным и доступным, один временный `request_code` идёт напрямую с IP VDS, последующие действия — через назначенный прокси. Отрицательный или неопределённый исход запроса кода не запускает автоматический повтор. Правило одного подтверждённого сообщения в назначенный день недели и `unknown` без автоматического повтора сохранено.

На этой ветке прошли 71 обычный Python-тест, 8 браузерных, Node-тест, JS syntax, `pip check`, `docker compose config --quiet` и `docker compose build app`. GitHub CI указывается после фактического завершения в [журнале](change-log.md). Живые OTP, вступление и отправка MAX этими проверками не подтверждаются. Ревизия VDS, производственная резервная копия и восстановление требуют проверки через консоль провайдера; прежний `/health` нельзя считать подтверждением этого выпуска.
