# Техническое задание MAXBOT v2

## Назначение и пользователи

Новый приватный проект для одного владельца кабинета. Логин фиксирован: `edifier8989`. Начальный пароль вводится при установке через интерактивный хешер, в Git и образ не попадает. Пароль хранится как bcrypt-хеш; cookie — HttpOnly/Secure/SameSite Strict; изменения требуют CSRF-токен и проверку Origin. Регистрации, админа, ролей, организаций и подписок нет.

## Группы, аккаунты и подключения

Группа содержит имя, MAX invite link, закреплённый chat ID, статус и собственные прокси. MAX-аккаунт может принадлежать только одной группе. У владельца кабинета есть операция создать/перевыпустить/отозвать гостевую ссылку с TTL 7 дней и ограничением количества подключений. Гость сообщает ФИО/телефон, проходит OTP и, если нужно, cloud password, затем самостоятельно открывает MAX invite link и вступает в группу. Приложение не автоматизирует вступление; оно проверяет членство. Первый успешно авторизованный номер разрешает chat ID группы через PyMax; следующие обязаны совпасть. Смена MAX invite link отзывает onboarding token и сбрасывает chat ID до повторной проверки.

## Прокси

Прокси назначается до авторизации из пула группы: минимальная текущая загрузка, при равенстве — меньший `position`. Назначение постоянно, пока владелец явно его не изменит. Один маршрут используется на каждом внешнем действии номера. URL шифруется Fernet-ключом, интерфейс и журналы показывают только безопасную подпись. Нет прокси, отключённый или недоступный маршрут — блокировка; прямой маршрут запрещён.

## Расписание и отправки

Неделя — понедельник–воскресенье в редактируемой тайм-зоне (по умолчанию `Europe/Moscow`). День назначается один раз по наименьшей загрузке. Максимум — одно подтверждённое MAX сообщение на аккаунт за неделю. На группу запускается одна последовательная worker-задача; между группами допустим параллелизм. Автозапуск включён, восстанавливается после рестарта; доступны общий стоп и остановка группы. Если назначенный день истёк, слот становится пропущенным и не переносится.

Перед вызовом PyMax создаётся долговечная операция. Статус «принято» выставляется только с ID ответа. Только доказанный отказ до отправки допускает три попытки в назначенный день с паузами 5/15 сек. Таймаут или любой неопределённый ответ помечает слот `unknown`, автоматически не повторяется и требует ручной сверки. После перезапуска `in_flight` становится `unknown`.

## Тексты и настройки

Один общий текстовый пул поддерживает редактирование и импорт TXT. Версия пула содержит сохраняемую перемешанную очередь без повтора до конца цикла. Обновление пула создаёт новую версию и цикл; уже подготовленный слот сохраняет свой текст.

Настройки владельца: тайм-зона, окна будней `09:00–13:00, 16:00–21:00`, окна выходных `11:00–14:00, 17:00–20:00`, интервал между отправками `5–15` секунд и автозапуск. Дневные лимиты, разогрев, искусственная активность и внеплановая ручная отправка в v2 отсутствуют.

## Архитектура и безопасность

Один Python 3.12/FastAPI-процесс, одна SQLite база с WAL, Docker Compose, Caddy HTTPS. PyMax закреплён на 2.4.1 и используется через единственный адаптер. PostgreSQL/Redis/Celery не используются. Сессии PyMax сохраняются шифрованными файлами; временная рабочая SQLite копия живёт только в tmpfs. База содержит группы, аккаунты, прокси/назначения, гостевые ссылки и сессии, версии пула, слоты, операции, журнал и настройки. Внешние вызовы требуют операторской записи разрешения, действительного срока и области действия; по умолчанию они закрыты.

Защиты: лимит входа, HTTPS cookie, CSRF/Origin, истечение сессии и гостевых ссылок, лимиты OTP реализуются в координации PyMax, отсутствие прямого соединения при проблемах с прокси, отсутствие секретов в UI и журналах. Номера, URL прокси и данные авторизации не пишутся в audit detail.

## Приёмочные проверки

10 групп / 100 аккаунтов; последовательная отправка внутри группы и параллельные группы; отсутствие второго принятого сообщения за неделю после повтора/рестарта; устойчивость дня, proxy assignment и текста слота; пропуск истёкшего дня; отсутствие повтора при неизвестном результате; цикл сообщений без повторов; первый и повторные гостевые подключения; истёкшая/отозванная/исчерпанная ссылка; отказ прямого соединения; резервная копия и проверяемое восстановление. Все автоматические тесты используют фиктивный PyMax.
