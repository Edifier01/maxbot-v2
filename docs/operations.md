# Эксплуатация

## PyMax и прокси

Авторизация, проверка членства и отправка выполняются через единственный адаптер PyMax и назначенный аккаунту прокси. Прямое соединение не используется. Перед подключением проверьте MAX-ссылку, доступность прокси и выбранный аккаунт. Ответ на запрос кода означает только, что MAX принял запрос; он не подтверждает, что SMS доставлена.

Для диагностики используйте безопасные INFO/WARNING-события приложения: ID попытки, аккаунта и прокси, этап `request_code` / ожидания ввода / `send_code` / 2FA, длительность и класс ошибки. Ошибка проверки кода отделена от таймаута ожидания; ответ PyMax на запрос кода не подтверждает доставку SMS. Не включайте подробные логи PyMax без фильтрации: они могут содержать URL прокси. Проверяйте по одному условию за раз и соблюдайте лимиты MAX.

## Выпуск и резервное копирование

Перед обновлением проверьте конкретный SHA `main`, конфигурацию Compose, версию контейнера, состояние тома и логи. Убедитесь, что кнопка остановки выключила новые отправки. Затем штатно остановите приложение и сделайте общий архив SQLite и зашифрованных session files:

```sh
docker compose stop app
docker compose run --rm --no-deps app python scripts/backup.py /data/backups/maxbot-$(date -u +%F).zip
```

Архив содержит SQLite snapshot и только зашифрованные файлы сессий. Храните `DATA_ENCRYPTION_KEY`, `APP_SECRET_KEY` и пароль владельца в отдельном секретном хранилище, отдельно от архива и Git.

До переключения трафика восстановите копию в пустую отдельную директорию и проверьте `PRAGMA integrity_check`. Не подключайте восстановленный каталог к production. Проверьте чтение аккаунтов и сессий при том же `DATA_ENCRYPTION_KEY`, затем удалите тестовую среду после фиксации результата.

При сборке передайте полный SHA в аргумент `BUILD_REVISION`, например `BUILD_REVISION=<main-SHA> docker compose build app`. `/health` возвращает установленный `revision`. Сверьте его с GitHub SHA и локальным checkout. Проверьте HTTPS, Caddy, заголовки клиентского IP и то, что порт приложения не опубликован напрямую. Не меняйте Caddy до успешной проверки восстановления.

## Проверка PyMax при выпуске

Сравните для успешного локального запуска и VDS версию/путь Python, `maxapi-python==2.4.1`, версию Android-клиента MAX, наличие сохранённой сессии и назначенный прокси. Последовательно проверьте локально без прокси, локально с прокси, на VDS, затем в веб-интерфейсе. Для каждого шага сохраните безопасные журналы и не включайте код, токен, пароль, телефон или URL прокси.

Реальную SMS-авторизацию и тестовую отправку проводите только в согласованной тестовой группе. Сначала проверьте доставку кода, вход, членство, сохранение сессии и вход после рестарта без нового кода. Тестовое сообщение отправляйте только после проверки адресата и содержимого.

## Откат

Не очищайте том и не пересоздавайте базу для отката. Остановите отправки, сохраните текущий архив, верните предыдущий проверенный образ и конфигурацию, затем сверьте `/health` и журнал операций. Архивирование или удаление старых веток/worktree — отдельная операция после сверки Git и сохранения пользовательских файлов.
