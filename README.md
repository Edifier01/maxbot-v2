# MAXBOT v2

Однопользовательская панель для распределения недельных сообщений по MAX-группам. Приложение рассчитано на новую чистую установку; старые группы, сессии и история не импортируются.

## Состояние

Создан каркас FastAPI + SQLite, базовая панель, защищённый вход, настройки, текстовый пул, гостевые ссылки, назначения прокси/дней, подготовка недельных слотов, последовательные worker-задачи групп и журнал долговечных операций. PyMax изолирован в `maxbot_v2/max_adapter.py` и закреплён на `maxapi-python==2.4.1`.

Проверки используют локальную SQLite и фиктивный адаптер. Реальную авторизацию и отправку MAX в этой среде не выполняли. Внешние действия по умолчанию заблокированы; для разблокировки приложение требует операторскую запись разрешения с действующим сроком, ссылкой на договор и требуемыми областями действия. Она не хранится в Git и монтируется в контейнер как Docker secret.

## Разработка и запуск

Нужны Docker Compose и домен, указывающий на VPS. Скопируйте `.env.example` в `.env`, задайте уникальные `APP_SECRET_KEY` и `DATA_ENCRYPTION_KEY`, а хеш начального пароля владельца получите интерактивно:

```powershell
python -m pip install -r requirements.txt
python scripts/hash_password.py
```

В `.env` внесите полученный `OWNER_PASSWORD_HASH`, домен и случайные ключи. Сам пароль не записывайте в файлы проекта. Сгенерировать ключ шифрования можно через `python -c "from maxbot_v2.crypto import SecretBox; print(SecretBox.generate_key())"`.
Секрет приложения можно создать через `python -c "import secrets; print(secrets.token_urlsafe(48))"`.

Затем запустите `docker compose up -d --build`. Caddy получает TLS-сертификат автоматически; приложение слушает только внутреннюю сеть Compose. Для включения реальных действий создайте вне репозитория файл разрешения `max-authorization.json`, смонтируйте его в сервис `app` как read-only secret по пути из `MAX_AUTHORIZATION_FILE`. Формат описан в [разделе защиты действий](docs/operations.md). Без него вход, настройки и тестовая работа доступны, а операции MAX закрыты.

## Резервная копия и восстановление

Архив включает SQLite через Online Backup API и зашифрованные файлы сессий. Ключ `DATA_ENCRYPTION_KEY` и секреты развёртывания хранятся отдельно от архива. Команды `scripts/backup.py` и `scripts/restore.py` создают и проверяют восстановление в пустую директорию; эксплуатационный порядок — в [docs/operations.md](docs/operations.md).

## PyMax

Используется только версия `maxapi-python==2.4.1`. Документация: [Client](https://docs.pymax.org/client.html), [ExtraConfig](https://docs.pymax.org/api/client-config.html), [Messages](https://docs.pymax.org/messages.html). Клиент подключается с закреплённым прокси и отдельно зашифрованным session snapshot; временная SQLite-сессия находится в tmpfs контейнера. Эта интеграция опирается на неофициальный API MAX.
