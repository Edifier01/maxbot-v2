# MAXBOT v2

Однопользовательская панель на FastAPI, SQLite и обычном JavaScript для планирования сообщений в MAX-группах. Проект сохраняет данные и зашифрованные сессии из существующего `/data`; перед выпуском всё равно создайте и проверьте резервную копию. Поддерживаемая схема базы расширяется повторяемо без удаления пользовательских строк.

## Состояние

PyMax закреплён на `maxapi-python==2.4.1` и изолирован в `maxbot_v2/max_adapter.py`. При гостевой авторизации только один запрос SMS-кода (`request_code`) разрешён напрямую; перед ним проверяются включённое назначение, состояние `healthy` и возможность расшифровать URL прокси. Вызов выполняется отдельным временным клиентом без сохранения сессии. Проверка OTP, 2FA, вход, проверка членства и остальные действия используют назначенный прокси. При ошибке прокси прямого перехода нет. В коде проекта нет требования к отдельному файлу разрешения или договору.

Автоматические проверки используют отдельную SQLite и фиктивный PyMax. Они не доказывают доставку SMS или работоспособность конкретного прокси/MAX-аккаунта. Реальную проверку проводите на тестовом номере и группе с согласованным содержимым. После выпуска `/health` возвращает `revision` образа; значение `unknown` означает, что SHA не был передан при сборке.

## Разработка

Нужны Python 3.12 и Node.js 24. В Windows создайте окружение и установите зависимости разработки:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m pytest -q --ignore=tests/test_browser_workflows.py
.\.venv\Scripts\python.exe -m pytest -q tests/test_browser_workflows.py
node --check static/app.js
node --check static/join.js
node --test tests/test_join_start.cjs
```

На Linux установите браузер вместе с системными пакетами командой `python -m playwright install --with-deps chromium`. Запускайте обычные Python-тесты и Playwright отдельными командами: синхронный драйвер Playwright управляет циклом событий своего процесса. CI проверяет обе группы на Windows и Linux, JavaScript и сборку Docker на Linux. `requirements-dev.txt` содержит тестовые инструменты; производственный образ устанавливает только `requirements.txt`.

Создайте локальный `.env` из `.env.example`. Задайте уникальные `APP_SECRET_KEY`, `DATA_ENCRYPTION_KEY` и `OWNER_PASSWORD_HASH`. Хеш начального пароля создаётся интерактивно:

```powershell
.\.venv\Scripts\python.exe scripts/hash_password.py
```

Не сохраняйте секреты и реальные номера в Git или тестовых данных. Для первого локального запуска используйте отдельный каталог данных. Docker-режим запускается так:

```powershell
$env:BUILD_REVISION = (git rev-parse HEAD)
docker compose up -d --build
```

Caddy выдаёт TLS, а приложение доступно только во внутренней сети Compose. Кнопки «Запустить/Остановить» управляют работой сейчас; «Автозапуск после рестарта» задаёт состояние при следующем старте процесса.

## PyMax

Используется `maxapi-python==2.4.1`. Ссылки на первичную документацию: [Client](https://docs.pymax.org/client.html), [ExtraConfig](https://docs.pymax.org/api/client-config.html), [Messages](https://docs.pymax.org/messages.html) и [исходный код PyMax v2.4.1](https://github.com/MaxApiTeam/PyMax/tree/v2.4.1). TCP-клиент принимает прокси `http://` и `socks5://` с портом. Ссылки MAX-групп должны содержать `/join/`. Интеграция использует неофициальный API MAX.

Ответ PyMax на `request_code` не подтверждает доставку SMS. Не повторяйте автоматически запрос с неопределённым результатом и соблюдайте лимиты MAX. Для остальных действий не переключайтесь на прямое соединение при ошибке прокси. Не включайте сырые логи PyMax с URL прокси.

В гостевой авторизации перед запросом кода проверяются включённое назначение прокси и возможность расшифровать его URL. Затем один `request_code` выполняется временным прямым PyMax-клиентом без сохранения сессии. Ввод OTP, облачный пароль, вход и дальнейшие запросы выполняются основным клиентом через назначенный прокси.

При подключении российский телефон принимается с 10 цифрами, с начальной `7` или `8`, с кодом `+7` и с форматирующими разделителями; перед передачей PyMax приводится к `+7XXXXXXXXXX`. После авторизации приложение автоматически пробует вступить в группу по сохранённой ссылке MAX и подтверждает членство; если не получилось, гостю доступен ручной переход по ссылке и повторная проверка. Админка показывает понятные ошибки и состояние проверки прокси. Удаление номера скрывает его из панели, сохраняя историю и зашифрованную сессию.
